# CMS site example

A small site whose articles, authors, topics and settings live in a
database: a SQLite file, or PostgreSQL. Pages are rendered when content
changes (the `publish` render mode) and written to `public/`, so a web
server can serve them as files. Articles have cover pictures from the media
library, and `/search/` searches them.

It needs an engine built with the `cms` preset. From the repository root,
on SQLite (no server to install):

```sh
cargo build --release --features cms
export ENGINE_DATABASE_URL=sqlite://data/site.db    # relative to the site folder
E=./target/release/engine
S=examples/cms-site

$E types sync --site $S     # already done: migrations/ is committed
$E migrate --site $S        # create the tables (data/site.db)
$E media add --site $S $S/media-samples/harbour-at-dusk.jpg --alt "A harbour at dusk"
$E media add --site $S $S/media-samples/forge-yard.jpg --alt "A forge yard at sunset"
$E content seed --site $S   # demo content from seed/ (covers are media #1, #2)
$E build --site $S          # render every page, record the tag index, index search
$E user create --site $S --email you@example.org --name You   # first admin
$E serve --site $S          # serve public/, publish changes, the admin, search
```

On PostgreSQL instead, start one and point the URL at it (everything else is
the same):

```sh
docker compose -f deploy/compose.postgres.yml up -d --wait
export ENGINE_DATABASE_URL=postgres://wrought:wrought@127.0.0.1:55432/wrought
```

The sample pictures carry made-up GPS coordinates in their EXIF data;
`engine media add` (like an upload in the admin) removes them, and makes
copies 320 to 1280 pixels wide for `srcset`.

`user create` prints a one-time link to choose the password (or pass
`--password-stdin`). Then open <http://localhost:4400/admin/>, sign in, and
edit an article: `engine serve` rewrites only the pages that show it. Give
other editors the `editor` role, or make a role under **Roles** that, say,
may edit articles but only read their author. Two people saving the same
article get a conflict screen instead of overwriting each other.

The command line edits through the same code path:

```sh
$E content set --site $S article why-wrought-iron-lasts --set title="Why wrought iron endures"
```

What's in it:

| Path | Kind | Re-rendered when |
| --- | --- | --- |
| `/` | Markdown + `get_singleton("settings")` + latest articles | settings or any article change |
| `/articles/`, `/articles/page/2/`... | paginated list (`[routes.list]`, 5 per page) | any article changes |
| `/articles/{slug}/` | one page per published article, with its cover (`media()`, `image`) and related articles | that article, its author or its cover changes, or articles change |
| `/authors/{slug}/` | one page per published author | that author or any article changes |
| `/topics/`, `/topics/{term}/` | taxonomy | articles or topics change |
| `/about/` | Markdown, publish mode | never by content edits |
| `/search/` | `request` mode: `search_box` and `search_results` | rendered per request (`?q=`), never stored |
| `/account/` | `request` mode, `requires = "auth"` | rendered per request, never stored |
| `/media/...` | uploaded files and their copies (`data/media/`, not in git) | never: files do not change |
| `/admin/` | the admin (engine) | — |
| `/colophon/` | `build` route | only by `engine build` |

Files:

- `types/*.toml`: the content types (fields, relations, validation);
  `types/blocks/*.toml`: blocks used in `article.sections`.
- `migrations/postgres/`, `migrations/sqlite/`: generated by `engine types
  sync`; `migrations/types-snapshot.json` records what was synced.
- `media-samples/`: two generated pictures for `engine media add`.
- `seed/content.toml`: demo content.
- `templates/`: pages and `blocks/` templates.
