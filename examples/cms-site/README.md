# CMS site example

A small site whose articles, authors, topics and settings live in
PostgreSQL. Pages are rendered when content changes (the `publish` render
mode) and written to `public/`, so a web server can serve them as files.

It needs an engine built with the `cms` preset and a PostgreSQL database.
From the repository root:

```sh
cargo build --release --features cms
docker compose -f deploy/compose.postgres.yml up -d --wait
export ENGINE_DATABASE_URL=postgres://wrought:wrought@127.0.0.1:55432/wrought
E=./target/release/engine
S=examples/cms-site

$E types sync --site $S     # already done: migrations/ is committed
$E migrate --site $S        # create the tables
$E content seed --site $S   # demo content from seed/
$E build --site $S          # render every page, record the tag index
$E serve --site $S          # serve public/ and publish changes
```

In another terminal, change an article and watch `engine serve` rewrite
only the pages that show it:

```sh
$E content set --site $S article why-wrought-iron-lasts --set title="Why wrought iron endures"
```

What's in it:

| Path | Kind | Re-rendered when |
| --- | --- | --- |
| `/` | Markdown + `get_singleton("settings")` + latest articles | settings or any article change |
| `/articles/` | template listing | any article changes |
| `/articles/{slug}/` | one page per published article | that article or its author changes |
| `/authors/{slug}/` | one page per published author | that author or any article changes |
| `/topics/`, `/topics/{term}/` | taxonomy | articles or topics change |
| `/about/` | Markdown, publish mode | never by content edits |
| `/colophon/` | `build` route | only by `engine build` |

Files:

- `types/*.toml`: the content types (fields, relations, validation);
  `types/blocks/*.toml`: blocks used in `article.sections`.
- `migrations/postgres/`: generated by `engine types sync`;
  `migrations/types-snapshot.json` records what was synced.
- `seed/content.toml`: demo content.
- `templates/`: pages and `blocks/` templates.
